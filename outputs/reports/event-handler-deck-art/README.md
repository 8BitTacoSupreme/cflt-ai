# Event Handler Design Patterns — art assets

Sixteen slide graphics for `../event-handler-patterns-playbook-deck.md` (v1.1).
All output is **SVG** — vector, so it scales into PowerPoint / Google Slides / Keynote
without resampling, and the text stays selectable and editable.

```
mmd/    mermaid sources for the 10 diagram assets
svg/    all 16 finished assets  ← this is what goes in the deck
png/    1600×900 rasters, for review only, not for the deck
build.sh    re-renders mmd/ → svg/ via mermaid-cli
preview.mjs rasterises svg/ → png/ for visual checking
mermaid-config.json  shared theme, so mermaid output matches the hand-drawn assets
```

## The three corrections carried in the art

1. **`art-03`** — v1.0's tree could route an *external* sink to Transactional EOS via the
   `state? No → duplicate visible? Yes` path. EOS does not cross the cluster boundary, so that
   branch recommended something that cannot work. An `Is the effect inside Kafka?` node now
   gates both EOS terminals, and the external path terminates in the amber
   "EOS cannot cross this boundary" box.
2. **`art-06`** — v1.0 flowed `retry topic → delay consumer → {retry succeeded?}`, implying
   delay consumers run business logic. They wait and re-publish. The ladder is now a contained
   subgraph feeding a single re-publish node, drawn as a return node rather than a back-edge so
   the diagram reads left to right.
3. **`art-11`** — compatibility checking and Data Contract rules are now two distinct gates,
   which is what makes S25's "syntactic, not semantic" caveat visible rather than verbal.

## Palette

Shared by the mermaid theme and the hand-authored SVGs, so the deck reads as one system.

| Role | Hex |
|---|---|
| Primary / text | `#173A6C` |
| Accent | `#0074E4` |
| Secondary accent | `#00A6A0` |
| Warning / error path | `#F2A900` (fill `#FDF3DC`) |
| Neutral text | `#5A6572` |
| Surfaces | `#EAF1FA`, `#E3F5F4`, `#F4F6F8` |

Amber is reserved for error paths and for the one thing on a slide that must not be missed.
Do not use it decoratively — the EOS crossing arrow on `art-14` and the DLQ nodes rely on it
being rare.

## Regenerating

```bash
bash build.sh                 # all mermaid assets → svg/
node preview.mjs              # all svg → png for review
node preview.mjs art-06       # just one
```

`build.sh` pulls `@mermaid-js/mermaid-cli@11` via `npx` (downloads Chromium on first run).
The hand-authored assets — `art-01`, `art-09`, `art-10`, `art-13`, `art-14`, `art-15` — are
edited directly in `svg/` and are **not** regenerated by `build.sh`.
